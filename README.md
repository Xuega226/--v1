# DeepSeek Agent 🤖

> 一个基于 DeepSeek API 的 AI 助手，支持工具调用和上下文压缩。

## 简介

DeepSeek Agent 是一个可调用工具的 AI 助手喵！它通过 DeepSeek 大语言模型驱动，能够执行 Shell 命令、读写文件、列出目录等操作，并且自带**上下文压缩**机制，长对话也不怕爆 token 喵~

## 特性

- 🧠 **DeepSeek 模型驱动** — 支持 `deepseek-chat` 和 `deepseek-reasoner` 等模型
- 🔧 **工具调用** — 内置 bash、文件读写、目录列表等工具
- 📦 **上下文压缩** — 智能摘要历史对话，节省 token
- 🔄 **交互 & 单次执行** — 既支持聊天模式，也支持命令行直传
- ⚙️ **高度可配置** — 模型、token 限制、温度等均可通过 `.env` 配置

## 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置 API Key

复制 `.env.example` 为 `.env`，填入你的 DeepSeek API Key：

```bash
cp .env.example .env
# 编辑 .env 文件，填入 DEEPSEEK_API_KEY
```

### 3. 运行

**交互模式：**

```bash
python main.py
```

**单次执行：**

```bash
python main.py "帮我看看当前目录有什么文件"
```

**指定模型：**

```bash
python main.py --model deepseek-reasoner "1+1等于几？"
```


在交互模式下，可以使用以下命令：

|------|------|
| `/exit` | 退出程序 |
| `/reset` | 重置对话历史 |

## 配置项

所有配置项可通过 `.env` 文件或环境变量设置：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `DEEPSEEK_API_KEY` | — | DeepSeek API Key |
| `DEEPSEEK_MODEL` | `deepseek-chat` | 模型名称 |
| `AGENT_MAX_TOKENS` | `4096` | 单次生成最大 token 数 |
| `AGENT_TEMPERATURE` | `0.7` | 生成温度 |
| `AGENT_MAX_TURNS` | `20` | 单轮对话最大工具调用轮次 |
| `AGENT_COMPRESS_THRESHOLD` | `8000` | 触发上下文压缩的 token 阈值 |

## QQ 社交状态与自然群聊

QQBot 会先用本地规则判断是否值得接话，只有确定回复时才调用聊天模型。社交状态保存在
`qq_sessions/social_state.json`，包括：

- 跨群共享的熟悉度、好感、信任、警戒和少量重要事件；
- 会随时间衰减的全局心情；
- 按群隔离的当前话题和短期发言线程，避免串群接错话；
- 对“明天考试”等未完事项的低频自然回访；
- 分阶段风险行为：提醒、冷淡、达到阈值后静默。

每次真正回复只注入不超过 `QQ_SOCIAL_CONTEXT_CHARS` 个字符的社交摘要，不会把完整记录
放进模型上下文。主人可以使用以下管理命令：

| 命令 | 说明 |
|------|------|
| `/mood`、`/mood reset` | 查看或重置当前情绪 |
| `/social`、`/social QQ号` | 查看本群状态或指定群友关系 |
| `/socialreset QQ号` | 重置指定群友的关系状态 |
| `/riskreset QQ号` | 清除风险计数和警戒状态 |

全部群聊、私聊、世界书、跑团、图片、语音和启动指令见
[QQBot指令集合.md](QQBot指令集合.md)。

## QQ 世界书

QQBot 支持 SQLite + Qdrant 世界书：永久规则确定性注入，普通条目使用关键词、
正则和本地中文向量混合检索。聊天历史仍保持原有策略，每轮只注入约
`WORLD_BOOK_CONTEXT_TOKENS` 个相关 token。

1. 启动 Qdrant：`docker compose -f infra/qdrant/compose.yaml up -d`
2. 把世界书放入 `qq_workspace/worldbooks`
3. 在群里执行 `/world import 文件名.json 名称`
4. 执行 `/world use 名称`；仅跑团使用则执行 `/world use 名称 trpg`

完整格式和命令见 [qq_workspace/worldbooks/README.md](qq_workspace/worldbooks/README.md)。

## QQ 图片识别

QQBot 可通过本地 PaddleOCR + Qwen3-VL 识别 QQ 图片和被回复消息里的图片：

1. 启动 CPU OCR：`docker compose -f infra/vision/compose.yaml up -d`
2. 确认 Windows Ollama 已运行，首次执行：`ollama pull qwen3-vl:2b`
3. 在 QQ 中发送图片并 @机器人、说“看看这张图”，或回复图片说“看看”
4. 用 `/vision status` 查看 OCR、视觉模型和识别缓存状态

跑团中发给机器人的图片会自动识别。同一轮只处理第一张，识别结果按图片哈希缓存，
并且只进入当前轮提示，不会把大段图片描述永久塞进聊天上下文。具体部署与降级行为见
[infra/vision/README.md](infra/vision/README.md)。

## 未名子原生桌面 Agent

桌面版采用“常驻 Python 核心 + WPF 原生窗口”。窗口只是身体和聊天入口，关闭窗口不会让
核心离线；再次打开时会接回相同的生活状态、长期记忆和桌面对话。

首次使用或窗口意外关闭时都直接双击项目根目录的 `start_desktop_agent.bat`。脚本会检查核心与窗口，
只启动缺失的部分，并在需要时构建 WPF 窗口。不要直接双击 `bin/Release` 里的
`Unnameko.Desktop.exe`：该程序依赖项目自带的 `.dotnet`，绕过启动脚本会触发“缺少 .NET”提示。
窗口右上角的按钮只会隐藏到托盘；托盘菜单的“退出窗口”也会保留核心在线。
需要让核心保存状态并真正停止时，双击 `stop_desktop_agent.bat`。

也可以在终端查看核心状态：

```powershell
.venv\Scripts\python.exe desktop_agent_core.py --status
```

第一版允许她读取授权工作目录、查资料、使用语音和轻量随机工具，不允许改写文件、执行命令
或直接控制电脑。运行数据位于 `agent_sessions`，长期记忆和活动账本继续与 QQ 侧共享；
QQ 离线不会影响桌面核心。

### 桌面任务与权限确认

窗口的“任务”页支持“自然语言目标 → 计划预览 → 主人确认计划 → 逐步执行”。模型会把目标
整理成 1 至 6 个可检查步骤；模型不可用时会生成保守的本地草案。计划确认与操作授权彼此
独立：确认计划只允许开始推进，首版仍仅允许在 `agent_workspace` 创建新的文本文件。

- 计划草案只保存目标和步骤，不会生成写入许可，也不会立即写文件；
- 主人可预览步骤、目标路径和待写内容，并选择确认或放弃；
- 无副作用的 `content.prepare` 可自动推进，每个 `workspace.write_text` 都会单独弹出权限卡；
- “允许一次”只授权当前一个步骤，多文件计划不会共享授权；
- 拒绝或 15 分钟内没有决定会取消任务；
- 禁止绝对路径、`..`、隐藏目录、脚本和可执行文件；
- 目标文件已经存在时拒绝执行，永远不会自动覆盖；
- 目标、任务、步骤、幂等键、审批和结果都保存在 `agent_runtime.db`，重启后仍可查看。

任务系统 2.0 还支持：

- 重新生成计划、编辑第一份输出、查看规划耗时和完整降级原因；
- 暂停、继续、取消和最多三次安全重试；多个耗时任务在核心内串行排队；
- “查资料/研究/带来源”目标会执行只读联网检索，整理带链接来源的 Markdown，完整内容生成后才请求写入；
- 在专属工作区修改或追加 UTF-8 文本时展示差异，并把旧内容保存到 `.versions`；
- 经单次许可创建目录和重命名；仍不允许删除、执行脚本或操作专属工作区之外的文件；
- 主人可以建立持久化定时提醒，核心重启后仍会按时发送本地托盘提醒；
- 完成后的文件可从任务列表直接打开，只有验证成功的结果会写入活动账本和任务经历记忆。

### 主动陪伴与待续事项

桌面核心会把真实任务完成、长期记忆中的待续事项、连续使用时长和深夜活跃转换成主动候选，再统一检查
静默时间、临时安静、全屏、离开电脑、最近对话、其他桌面通知、每日预算和反馈习惯。候选没有通过本地
仲裁时不会调用语言模型。通过后可用一个不带聊天历史、世界书或工具定义的小提示润色一到两句话；超时、
校验失败或模型不可用时立即使用本地模板。

“主动”页可以查看她为什么暂时不出现、实际润色 Token、最近时间线和结构化待续事项。待续事项区分等待、
延期、等待结果、已解决、已放弃和关闭；主人可以手动标记解决、延后一天或不再询问。长期愿望只会保留，
不会被当成近期承诺反复追问。连续三次以上的回应、稍后或关闭反馈才会调整最小间隔和久坐阈值，单次点击
不会永久改变习惯，并可随时恢复默认节奏。主动提议只能建议下一步，仍需主人确认计划和每个写入权限。

### 项目连续性与下一步建议

第三版用 `agent_sessions/desktop_projects.json` 把目标、任务、步骤产物、失败问题和后续建议连接成持久项目。
“项目”页展示项目状态、原始目标、任务/产物数量和可解释建议。完成演示文稿、文档或失败任务时，本地规则会
从文件类型、任务状态和尚未登记的质量检查中生成机会，记录依据、对象、风险、价值评分和建议目标；重复事件
或重启不会生成重复机会。

建议卡的“生成计划预览”只把建议目标送回原有任务页，主人仍需检查并主动点击生成计划，之后仍经过计划确认
和逐步写入权限。由建议产生或重新生成的任务会继续归属于原项目，完成后关闭原建议并登记新的产物或问题。
项目可以归档，归档时尚未处理的主动建议同步关闭。

主动消息现在记录等待、排队、发送、显示和处理状态。WPF 收到气泡后回传显示确认；发送前断线的消息会在重连
后恢复，已经显示的消息不会再次弹出。两个以上同时到期的低优先事项会合并成一条摘要，高优先级的任务完成与
权限消息始终优先。机会发现和摘要合并完全在本地执行，只有最终通过仲裁的一条表达可能调用语言模型润色。

### 第六版拟人化自主性

第六版把一次自主行动记录为“情境快照 → 自主意图 → 权限匹配 → 有界执行 → 本地复核 → 主人反馈”。
她不会让聊天模型临时编造动机；每个新意图都会保存项目、真实依据、为什么现在做、预期帮助、风险、完成标准、
使用的能力卡和状态迁移。窗口“自主”页可以直接查看她现在想做什么，以及对应的生活时间线。

主人可以为当前项目启用 7 天的“项目陪跑助手包”或“研究助手包”。权限包只是组合既有低风险能力：在专属
草稿区创建新文件、读取已登记项目文本、生成不落盘的差异预览，以及限量读取公开网页；不会赋予修改正式文件、
删除、执行程序、登录、上传、发布或向外发送的权限。撤销权限包时只撤销由该权限包新建的能力卡，不会误伤主人
此前单独授予的卡。所有结果先进入自主收件箱，正式采纳仍走原有任务计划和单次权限确认。

信任学习需要至少三份不同的同类工作得到连续正向反馈，且只在原能力卡内略微调整价值阈值和权限包每日额度；它永远不会
自行增加操作种类。负向反馈会收紧频率，“不再做此类”会直接禁用对应偏好。连续两次自主行动失败会自动熔断
六小时；主人可以手动允许一次安全试探，试探失败会立即重新熔断。第五版已有能力卡、草稿、收件箱和反馈均会
原样迁移；尚未完成的旧队列会补建可追溯意图，已经结束的历史不会被改写，新机会则从升级后的第一次仲裁开始完整记录。

### 记忆与一次性感知

WPF 的“记忆”页可查看长期/候选/归档记忆，支持主人修订、置顶和彻底遗忘。彻底遗忘会先显示
不可恢复确认，不提供隐蔽的自动删除。

“感知”页默认全部关闭。剪贴板文本、最近活动窗口标题、Windows UI Automation 控件结构和窗口截图
都必须逐项勾选并点击；读取结果先进入可见预览，随下一条消息发送后清除。UIA 优先提供控件类型、名称、
状态与位置，密码控件的内容始终隐藏；读不到自绘或游戏界面时再由截图、OCR 与视觉模型兜底。一次性截图
只保存在系统临时目录，识别完成后立即删除，桌面截图的归一化副本与识别缓存也会同步清除。
预览中已有内容时，可以在对话框输入具体问题再发送；输入框留空直接点击“发送”，则会自动请未名子概括
刚刚授权的桌面内容。

感知页提供三种可持久保存的权限策略：

- `隐私模式`：保留逐次勾选许可；
- `陪伴模式`（默认）：点击读取按钮本身即代表一次授权，主人在聊天中说“看看这个窗口”“这里报错了”等
  话时也会自动读取最近活动窗口；普通聊天只附带非禁止应用的轻量活动状态，受信任应用可以附带窗口标题；
- `Agent 模式`：沿用陪伴模式，并用于较长的限时观察任务；看见与操作仍然分权，文件和系统操作不会因此
  跳过权限卡片。

策略可以按进程名维护信任名单和禁止名单，禁止名单始终优先。托盘菜单提供全局“暂停桌面感知”，暂停状态
会持久保存。感知页会分别说明本地处理和远程数据流：UIA、OCR、变化检测及 Qwen3-VL 在本机运行；只有
启用“发送筛选后的感知摘要”时，整理后的文字才会进入 DeepSeek 对话，截图原图不会发送给 DeepSeek。

“限时陪伴观察”必须单独授权，可锁定启动前最后使用的一个窗口 5 或 15 分钟。观察期间每 2 秒在本机
采集一次低分辨率变化样本和 UIA 结构，未变化时不调用视觉模型；只有额外勾选视觉许可后，明显变化才会
触发截图识别，并限制为最多 5 次、间隔至少 30 秒。标题栏会持续显示观察指示和剩余时间，手动停止、
目标窗口关闭、时间到期或桌宠窗口退出都会终止观察。系统不会后台轮询剪贴板，也不会默认开启连续感知。

### 桌宠表现层

WPF 窗口支持完整工作面板与紧凑桌宠两种形态。完整面板用于对话、任务、项目、记忆、主动和感知管理；点击标题栏的
桌宠按钮可缩成靠近桌面边缘的陪伴形态，拖动头像可移动，双击头像可返回完整面板。窗口形态和位置会保存在
当前 Windows 用户的本地应用数据目录中，下次启动自动恢复。

紧凑形态提供限长说话气泡、摸摸头快捷互动、对话入口和核心连接状态。头像具有轻微呼吸与漂浮动效；回复、
联网检索、计划生成、截图识别和活跃任务会显示旋转工作光环，心情会改变柔光颜色。完整面板同时提供精力条、
非阻塞状态提示和带进度/状态色的任务卡片。所有动效仅属于 WPF 表现层，不会扩大核心权限或启动后台感知。

头像表现由独立状态机驱动，内置平静、开心、害羞、担心、困倦和专注六种基础表情。状态机设置最短保持时间，
并按工作、错误、权限等待、心情、精力和摸头互动切换，避免短时间内反复变脸。随机眨眼使用独立闭眼帧；流式
回复开始后使用闭口、半开口和张口三档循环，回复结束后立即恢复当前表情。图片资源只负责视觉显示，不接受模型
直接指定文件路径。

对话气泡会按中文或英文句末标点分段显示流式回复，最终只把完整回复记为一条历史；最近三条气泡可以在气泡底部
前后翻看。短回复留在桌宠气泡，桌宠模式下超过 220 个字符的回复会自动展开完整对话面板。气泡停留时间按字数
在 5–18 秒之间计算，鼠标悬停时暂停消失。回复、思考、联网工具、权限确认、提醒和错误使用不同标签与配色。
气泡只解析 HTTP(S) Markdown 链接与反引号行内代码，链接仅在主人主动点击后交给系统浏览器打开。
